# Bounded R32 image storage

`Image.Formatted` represents raylib format 8 (`R32`) as one little-endian
IEEE-754 binary32 sample per pixel, restricted to a checked domain so that the
existing infallible color/conversion APIs never hit undefined native
float-to-byte casts. It is not arbitrary float-image storage.

## Domain

The checked factory accepts finite values in `[0,1]`, including positive
subnormals and both zero signs. It rejects negative nonzero samples, values
above one, infinities and NaNs, in addition to the usual dimension, exact
byte-count and byte-value checks. Stored words and same-format/target-zero
conversions keep every sample bit, including negative zero and subnormals.

## ImageFormat semantics

- Formats 1..7 → R32 use native normalized channels and left-associated,
  uncontracted F32 luminance `(r*0.299 + g*0.587) + b*0.114`, without byte
  quantization.
- R32 → normalized channels is `(value, 0, 0, 1)`, not replicated grayscale.
- R32 → RGB/Surface produces red-only pixels with opaque alpha; R32 →
  grayscale therefore applies the luminance weight to the red component.
- `Image.Formatted.to_float_rgb` keeps the R32 word as red with positive-zero
  green and blue.
- Format 9 → R32 (`Image.FloatRGB.to_formatted(..., 8)`) computes the same
  direct uncontracted F32 luminance without byte quantization, clamping or tone
  mapping. All source components must be finite and in `[0,1]` (both zero signs
  and positive subnormals accepted); otherwise the original owner is returned
  with every bit intact, even when a weighted result would fit.
  `color_grayscale` remains format 1; targets 0/9 remain rejected.

The native API's "grayscale" conversion comment does not make every R32 query
gray. `Image.Formatted.colors/get` follow `LoadImageColors`/`GetImageColor` and
return red-only colors. The low-level `GetPixelColor` instead replicates the
R32 sample across RGB; `Pixel.get_color` does not support format 8.
`Image.Formatted.from_channel` redirects every valid selector to the sole R32
channel and returns an independent format-1 owner, keeping the source words;
selector-domain checks still apply.

The reference raylib build performs luminance with separate multiply and add
instructions. Other compiler/architecture contraction policies can change
final R32 bits; neither a fused mode nor parity on such profiles is claimed
(see [NATIVE-MATH-PROFILES.md](NATIVE-MATH-PROFILES.md)).

## Export and file boundaries

- `Image.Formatted.export`, `write_raw` and image-as-code exports keep exact R32
  words and metadata.
- `write_png` follows native file export: red-only normalized colors. The
  explicit `to_bmp`/`write_bmp` use the same red-only normalization and exact
  native V4 file bytes.
- `to_png` reproduces native **memory** export's different interpretation: each
  stored word is read as four little-endian byte channels and emitted as an
  8-bit RGBA PNG (not a floating-point PNG). For `0.5`, memory PNG decodes to
  `00 00 00 3f` while file PNG decodes to `7f 00 00 ff`. Success consumes the
  owner. Packed formats 3/5/6 still return the unchanged owner with
  `UnsupportedPixelFormat`: their native default four-channel reads would exceed
  two-byte-per-pixel storage.
- Explicit formatted QOI export rejects format 8 before conversion or file IO,
  keeping every R32 word; native QOI export accepts only RGB888/RGBA8888.
- `load_raw(..., 8)` accepts the same checked words through bounded positional
  reads and the native fitting-header/fallback-to-zero rule. The file is closed
  before checked construction; complete out-of-domain payloads return
  `InvalidRawSamples`, distinct from truncation and invalid requests. Format 9
  is not accepted there; use `Image.FloatRGB.load_raw`. See
  [RAW-FILES.md](RAW-FILES.md).

Export details for every format are in [IMAGE-EXPORT.md](IMAGE-EXPORT.md).

## How it is verified

Expected bytes always come from pinned native raylib, never from Python
arithmetic. Lanes are CPU-1, CPU-2 and JavaScript (see
[VERIFICATION.md](VERIFICATION.md)).

- **Conversions** (`tools/image_format_probe.py`, gate `image-format`): all 64
  `ImageFormat` pairs over formats 1..8, chains, boundary samples and
  rejected-factory controls, including every word of a 33,024-pixel
  signed-zero/subnormal import.
- **Consumers** (`tools/r32_image_probe.py`, gate `r32-image`): retained source
  words, channel extraction, format-9 red words, color queries, memory-PNG
  encoded bytes and decoded RGBA, file PNG/RAW/code files, and the explicit
  rejections (packed memory PNG owners, out-of-domain FloatRGB→R32,
  `GetPixelColor`, format-9 RAW loading). Pure operations can also run on a
  forced-GPU lane (`--gpu`); file IO runs on CPU/JavaScript only.
- **Format 9 → R32** (`tools/float_rgb_r32_probe.py`, gate `float-rgb-r32`):
  expected bytes come from pinned `ImageFormat`, including both non-identity
  round-trip chains. The archive's uncontracted arithmetic is qualified first.
  Inputs cover signed-zero and unit corners, predecessors of one,
  subnormal/normal boundaries, packed/grayscale thresholds, a contraction
  discriminator, seeded exponent-spread samples, thin shapes and a
  33,024-pixel image; rejected inputs put each bad component at early, middle
  and final positions and compare original and copied owners completely. NaNs
  are checked on the same backend only.
- **RAW loading** (`tools/r32_raw_file_probe.py`, gate `r32-raw-file`): see
  [RAW-FILES.md](RAW-FILES.md#how-it-is-verified).

```sh
python3 tools/run_gates.py --bend-source "$BEND_SOURCE" --raylib-source "$RAYLIB_SOURCE" --only r32-image
```

## Known gaps

Wider float domains, float/half/compressed layouts beyond this profile,
mipmaps, native ABI, numerical contraction variants, and full
platform/integration/resource/performance coverage.
