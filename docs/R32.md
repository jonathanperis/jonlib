# Bounded native R32 image storage

`Image.Formatted` additionally represents raylib format 8 (`R32`) as one
little-endian IEEE-754 binary32 sample per pixel. The checked factory accepts
finite values in `[0,1]`, including positive subnormals and both zero signs.
It rejects negative nonzero samples, values above one, infinities and NaNs,
alongside the existing dimension, exact byte-count and byte-value checks.

This bound preserves the existing infallible color/conversion APIs without
exposing undefined native float-to-byte casts. It does not promise arbitrary
float-image storage. Stored words and same-format/target-zero conversions retain
every sample bit, including negative zero and subnormals.

## ImageFormat semantics

- Formats 1..7 → R32 use native normalized channels and left-associated,
  uncontracted F32
  luminance `(r*0.299 + g*0.587) + b*0.114`, without byte quantization
- R32 → normalized channels is `(value, 0, 0, 1)`, not replicated grayscale
- R32 → RGB/Surface produces red-only pixels with opaque alpha; R32 → grayscale
  consequently applies the additional luminance weight to the red component
- `Image.Formatted.to_float_rgb` preserves the R32 red word with positive-zero
  green and blue. `Image.FloatRGB.to_formatted(..., 8)` remains unsupported

The native API's “grayscale” conversion comment does not make all R32 queries
gray. `Image.Formatted.colors/get` follow `LoadImageColors`/`GetImageColor` and
return red-only colors. The low-level `GetPixelColor` instead replicates its R32
sample across RGB; `Pixel.get_color` does not acquire format-8 support here.

`Image.Formatted.from_channel` redirects every valid selector to the sole R32
channel, returns an independent format-1 owner, and preserves the source words.
Existing selector-domain checks still apply.

## Export boundaries

`Image.Formatted.export`, `write_raw` and image-as-code exports retain exact R32
words and metadata. `write_png` follows native file export's red-only normalized
colors. `to_png` preserves native memory export's different interpretation:
each stored R32 word is read as four little-endian byte channels and emitted as
an 8-bit RGBA PNG. It is not a floating-point PNG encoding. For `0.5`, memory
PNG decodes to `00 00 00 3f`, while file PNG decodes to `7f 00 00 ff`.
Success consumes the checked owner, just like the supported byte formats.
Packed formats 3/5/6 still return the unchanged owner with
`UnsupportedPixelFormat`; their native default-four-channel reads would exceed
their two-byte-per-pixel storage and are outside this bounded memory profile.
`load_raw(..., 8)` accepts the same checked words through bounded positional
reads and the native fitting-header/fallback-to-zero rule. The file is closed
before checked image construction; complete out-of-domain samples return
`InvalidRawSamples`, distinct from truncation and invalid parameters. Format 9
remains unsupported in this loader; use `Image.FloatRGB.load_raw` separately.
See [RAW-FILES.md](RAW-FILES.md) for the exact request, error and closure contract.

Broader float domains, 9→8 conversion, float/half/compressed layouts beyond this
profile, mipmaps, native ABI, numerical contraction variants and complete
platform/integration/resource/performance coverage remain open.

The native raylib object on the recorded GCC 14 x86-64 host uses separate
multiply/add instructions for luminance. Other compiler/architecture contraction
policies can change final R32 bits; neither a fused mode nor parity on those
unverified numerical profiles is claimed.

## Verification

```sh
python3 tools/image_format_probe.py --bend-source "$BEND_SOURCE" --raylib-source "$RAYLIB_SOURCE"
python3 tools/r32_image_probe.py --bend-source "$BEND_SOURCE" --raylib-source "$RAYLIB_SOURCE"
```

The [current-host evidence](evidence/r32-image-format.json) records all 64 format
pairs across 165 native cases, 1,119 boundary samples and 45 rejected-factory
controls. CPU and JavaScript compare 173,303 complete native bytes per lane,
including all words in a 33,024-pixel signed-zero/subnormal import. Independent
review caught a non-tail validation draft; the final validation is tail-recursive.
The large test also exposed a separate Base `List.show` serializer stack limit,
resolved with strictly framed 256-byte output chunks without reducing inputs or
comparisons.

The initial bounded-storage consumer gate checked 82 pure observations and nine actual native
PNG/RAW/code files per CPU/JS lane. It verifies retained source words, independent
channels, direct format-9 red words, exact file contents and explicit rejection
of then-unsupported R32 memory PNG, RAW loading, reverse float conversion and low-level
pixel access. Native output, dimensions, byte counts and result counts are strict;
malformed/partial results cannot pass. The existing aggregate corpus still fails
on the separately documented [host angle profile](NATIVE-MATH-PROFILES.md).
The memory-PNG extension adds native encoded-byte and decoded-RGBA comparisons
for every R32 fixture, retains file-PNG comparisons, and explicitly checks all
three packed-memory rejection owners. Historical storage evidence above remains
dated; it does not stand in for the new memory-PNG evidence.

The [memory-PNG evidence](evidence/r32-memory-png.json) records 88 pure
observations, nine actual files and two RAW-load rejection controls per CPU/JS
lane. Across all 1,132 pixels, memory PNG compares 1,263 encoded bytes and 4,528
raw decoded bytes; file PNG separately compares 370 encoded bytes and 4,528
normalized decoded bytes. All packed rejection owners are checked exactly.
Eight contiguous candidate batches bound compilation size without dropping any
operation. Strict counts apply to each batch, so missing/extra results cannot
cancel across batches. Existing binaries were also replayed, retaining complete
stdout and reproducing every recorded output hash and comparison.

The [R32 RAW-load evidence](evidence/r32-raw-files.json) adds exact pinned-native
loads, headers/truncation, sample-domain rejection and descriptor-limited closure
checks on CPU/JS, including a 33,024-pixel import and invalid-final-word control.
The current R32 consumer regression retains all 88 pure observations, nine
exports, memory/file PNG distinctions and strict eight-operation serial batches.
Its two obsolete format-8 load rejections now test unsupported format 9 against
a valid present RGB-float payload and a genuinely missing path. The earlier
memory-PNG evidence remains a historical record of its then-current load scope.
